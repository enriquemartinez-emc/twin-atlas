Angular client setup

Task 003Donechore/init-client

A strict, modern Angular app, with guard rails that fail the build instead of relying on people to remember the rules.

Try it

cd client && npm start and open http://localhost:4200. Then npx ng lint: it passes, and it fails if you add an any type or an import that climbs out of a folder.

What was built

  • Angular 22.2 with TypeScript 6.0 on Node 24: standalone components, no zone.js, Vitest for tests, Tailwind v4 for styling.
  • Strict compiler settings: strict, noImplicitAny, noUncheckedIndexedAccess and strict templates, which the generated project did not enable.
  • Path aliases (@app, @features, @shared, @map, @api, @env) so imports never look like ../../...
  • ESLint rules that fail the build: no any, no ! non-null assertions, type-only imports where possible, no parent-relative imports, and a feature may only be imported through its public-api.ts. Later a rule against separate template and style files joined them.
  • Prettier with format and format:check scripts.
  • Angular 22 makes OnPush change detection the default, so components do not set it by hand.

Why it works this way

Rules a person has to remember get broken. Rules the compiler or linter enforces do not. Each guard rail here was proved by writing a throwaway file that breaks it and watching the check fail, then deleting the file.

How it was checked

CheckResult
Production buildZero errors and zero warnings. 195 kB at the time.
Unit tests (Vitest)Passing, including one that imports through every alias.
Lint with a planted violationany, ../.. imports, cross-feature files and ! all failed as intended; the public entry point was allowed.
PrettierClean.

Known limits

  • The Angular CLI also generated a client/CLAUDE.md and a .mcp.json that runs the Angular CLI helper through npx without a pinned version. They are harmless but unrequested.
