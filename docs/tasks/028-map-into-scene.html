Map into scene, and a review

Task 028In progresschore/map-into-scene

The Cesium map code lived in a folder of its own with a wrong excuse. It now sits inside the scene feature that is its only user, and a review of the whole Angular client found and fixed more leftovers of the same kind.

How to see it

Nothing looks different. Open client/src/app/features/scene. If the dev server was running, restart it: the path aliases changed again.

Why the map moved

src/app/map/ was kept apart, and AGENTS.md said "tools and aliases fix it". That was wrong: the alias was our own. Every import of it came from the scene feature, and Angular's style guide says to group code with the feature that uses it. So it is now features/scene/map/, and the @map/* alias and the lint rule about it are gone.

The review

I checked the client against Angular's style guide, the Angular developer skill and the CLI's own defaults.

AreaResult
Compiler and configStrict TypeScript and strict templates are on. app.config.ts has the global error listeners, withFetch and route-to-input binding. Build budgets are the CLI defaults and the initial bundle is far below them.
Old syntaxNone outside the generated Spartan files: no NgModules, *ngIf, @Input, lifecycle hooks, explicit OnPush or standalone: true.
Accessibility lintIt does run on inline templates. A deliberate image without alt text and a click on a non-focusable element each failed lint. The AXE checks that the client's guidelines ask for were not run: no AXE tool is installed.
FoldersThe scene folder held 13 files, two of them map overlays and two of them bar actions. They moved to map/ and scene-bar/. The scene folder itself now holds the page, its routes, its data and the workspace.
Leftovers fixedA second, identical CameraPosition type; type aliases and exports nobody used (some left over from the removed barrels); the client README still naming the old map path.
Handler namesThe style guide says to name handlers for what they do, not for the event. Six were named after events (onSubmit four times, onPick, onMapClick) and are now saveAnnotation, saveChanges, saveToken, createScene, chooseScene and applyMapClick.

Left as it is, on purpose

  • Single-file components. The style guide's default is a separate template and style file. This project keeps them inline, by your rule.
  • scene.ts at 430 lines. About 300 of them are its template and styles. Splitting the side panel out would need many inputs and outputs.
  • core/problems/ and shared/. Only the scene feature uses them today. They stay because they are not scene-specific: the error messages belong to the API, and the badge, alert and blank-title check are generic.
  • One environment file. The CLI's two-file setup is for builds that differ, and ours do not.
  • A method call in a template (isImported(item) in the annotation list). It is cheap and pure.

How it was checked

CheckResult
BehaviourAll 273 client tests pass; only import paths changed.
Lazy boundaryThe production build still shows map-viewer as its own 8.1 kB lazy chunk.
BuildFormatting, lint with the class check and the production build are clean.

Not verified

The app was not opened after the moves, and AXE was not run.
