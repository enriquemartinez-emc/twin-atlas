Redesign: tools, scene bar and panel

Task 023In progressfeat/ui-redesign

The screen was one tall card that held everything. Now the page has a bar for the scene, a column of tools on the map, a status bar, and a panel that shows one thing at a time.

How to see it

Reload the app. Read Using the app first: its diagram names every part. I have not looked at any of this in a browser yet.

What was wrong

Read from the code: copy link, the scene picker, New scene, the tools, the form, the editor, the list, the map details and the token box all lived in one 20 rem card with the same weight. The tools were bare words, "Marker" named the tool, the kind and every row, and developer details (source, camera) were always on screen.

What was built

  • Scene bar. The app, the scene chooser (Sim UI's "select with description", copied and adapted: each scene shows its name and the day it was made), a "New scene" dialog, a link button and a cog for the 3D tiles token.
  • Tool rail. Select, Marker, Note and Outline as icon buttons with tooltips. The active one is drawn in the colour of what it creates.
  • Hint. A pill that says the next step for the tool in hand, from one small tested function. It replaced the text inside the form.
  • Status bar. The map source (with a status dot, the second use of the badge copied from Sim UI), the camera, a button to go back to the starting view, and a spinner while the viewer starts.
  • Panel. It shows the list, or the form, or the editor, never two at once, and it sits on the right. Rows have an icon per kind (a pin, a speech bubble, a hexagon) and imported places carry an "OSM" badge. The filter shows an icon and a count per kind.
  • Comments. Comments that only restated the code were removed from the server and the client, about 420 lines. The ones that explain a decision stayed.

What the browser run found

With your approval I drove the running app (read-only: nothing was saved) and fixed what it showed.

  • Selection did not turn red. Picking a place from the list left its dot blue on the map, although the state was right. Cesium treats a remove and a re-add of the same id inside one batch as a change and keeps the old colour. The layer now removes first, then adds in a batch. A test that reproduces the batching fails on the old order.
  • The phone layout overflowed. The scene bar pushed its buttons over each other and the status bar covered the tools. "New scene" is now an icon on a phone, the dropdown is narrower, and the status bar sits under the tools.
  • The status bar covered Cesium's credits. It moved to the top, beside the tools.
  • Labels piled up. At 700 m a real import showed overlapping names. The label range went from 1,500 m to 300 m. It is still a judgement call.
  • Soft 3D tiles (found by you). Cesium rendered at CSS pixels, which looks blurry on a screen scaled above 100%, and loaded Google's tiles at its default coarseness. It now renders at the screen's real resolution and asks for finer tiles (error 8 instead of 16), which means more tile requests. Not looked at on a real Google tileset: that needs your token.
  • Smaller things. The scene dropdown wrapped long names, and the hide-panel button took a whole empty row.

New packages

You approved the icon packages: @ng-icons/core (MIT) and @ng-icons/lucide (ISC). With them came Spartan's dialog, tooltip, spinner and select. Spartan's tabs were dropped, because nothing needed a second tab once the map details moved to the status bar. The scene chooser first used Spartan's native select; you asked for the Sim UI dropdown, so it now uses Sim UI's "select with description" (MIT, notice kept). Everything else on screen is Spartan; the status-dot badge and this select are the two pieces taken from Sim UI.

How it was checked

CheckResult
Client tests242 pass (216 before). New: the hint rules, the tool rail, the status bar, the scene bar with its dialogs, the new scene form, and the panel swapping between list, form and editor.
Deliberate breaksEight, each failed a test: the scene chooser reporting the wrong scene, the hint ignoring a move, the rail never showing the active tool, the dialog staying open after a scene is created, the list shown next to the form, the list shown next to the editor, every kind counted as a marker, and the spinner never stopping. One break survived at first because the test only covered drawing, so a test for the editor was added.
Server193 tests pass after the comment cleanup; formatting is clean.
BuildLint with the class check, formatting and the production build are clean.

Not verified

The fixes made after the browser run (the red selection, the phone layout) were seen working on a second copy of the client, but the final code was not looked at again because the environment restarted. The README screenshots still show the earlier layout. The conflict message and moving a place were not exercised, because they write data.

Left for later

  • Map symbols with the same icons as the rail and the list. The map still draws coloured dots, so the list and the map do not fully match yet.
  • Moving the corners of an outline, and a delete.
