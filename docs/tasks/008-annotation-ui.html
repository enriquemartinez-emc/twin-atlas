Annotations on screen

Task 008In progressfeat/annotation-ui

The first screen you can use end to end: pick or create a scene, click the map, save, and see the result, all through a client generated from the server's contract.

Try it

docker compose up -d
cd server && ./mvnw spring-boot:run
cd client && npm start
  1. Open http://localhost:4200. The map starts on the Sagrada Família.
  2. In the panel, name a scene and press Create scene from this view.
  3. Press Marker, click the map, type a title and press Save.
  4. Save another marker with the same title: you get a plain sentence saying the title is already used.
  5. Press Outline, click three or more corners, give it a title and save.

What was built

  • A generated API client. The server publishes its contract as docs/openapi.json. A tool generates typed Angular code from it, so the app never hand-writes API types.
  • Typed shapes. The contract describes points and polygons as real GeoJSON types, so the client knows a Point from a Polygon.
  • Scenes. A list endpoint, a picker and "create from the current view". Your choice is remembered in this browser.
  • Annotations in view. The list and the map show what is inside the visible area. The previous result stays on screen while a new view loads, so the map does not flicker.
  • Placing things. Click for a marker or note, click corners for an outline, with a purple preview while you draw.
  • Readable errors. Each server code has a sentence. The message list is typed over the code list, so a new server code stops the client compiling until it has one.
  • Forms with Signal Forms and components that are single files.

How the screen is organised

SceneViewerPage the one smart component: owns the state, calls the services ScenePicker takes scenes, emits choose and create AnnotationForm takes kind and ready, emits submitted and cancelled AnnotationList takes items, emits selected IonTokenPanel takes the map mode, emits saved and forgotten services it calls ScenesService generated client, then /api/scenes AnnotationData generated client, then /api/scenes/{id}/annotations MapService loaded on demand, then Cesium

Only the page fetches and decides. The four small components just show what they are given and report what the user did, which makes them easy to test and reuse.

Why it works this way

Generating the client from a committed contract removes a whole class of "the server changed and the app broke" bugs (ADR 0008). During development the dev server forwards /api to the backend, so the browser sees one origin and no cross-origin setup is needed.

Known limits

  • No editing in this task. Annotations can be created and viewed here. Editing came next, with the ETag check (task 014; the glossary explains the ETag).
  • One page of up to 200 annotations is shown per view. If more are in view, the list says to zoom in.
  • The generated client contains two any types in its runtime. They are generated, so they are not edited, and the folder is excluded from the lint rule.
