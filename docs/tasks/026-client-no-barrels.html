Client without barrels

Task 026In progresschore/client-no-barrels

Research on Angular's own guidance and a measurement of our build showed that barrel files and folders named after code types were working against us. Both are gone, and annotations now live inside the scene feature.

How to see it

Nothing looks different. Open client/src/app/features/scene to see the new layout. This page replaces the folder layout described in Client structure tidy.

Partly replaced

The map/ folder shown here moved inside the scene feature in Map into scene, and a review.

What the research said

  • Barrels: Angular's style guide does not mention them. Its deferred loading guide warns that importing through an index.ts makes the bundler keep all the exports together, so a lazy piece ends up in the main bundle. It tells you to import from the file itself.
  • Folders: the style guide says to organize by feature area, to keep tests next to their code, and to avoid folders named for the type of code, such as components/ and services/. It does not mention core/, shared/ or features/; those are community convention.

What our build showed

Lazy chunkWith the map barrelStraight from the file
map-viewer119 bytes, a stub7.85 kB, the real code
scene277.7 kB269.4 kB

The viewer's code had been pulled into the scene chunk, which defeated the lazy loading set up on purpose. The loss is small because Cesium itself is still its own 5 MB chunk, but the design promise was not true.

What changed

  • Barrels removed. The three index.ts files and the @map alias are gone. Every import names the file that defines what it uses.
  • One feature. Annotations only exist inside a scene (on the server too), so features/annotation/ became features/scene/annotation/. There is no longer anything crossing between features.
  • Folders named for what they are. components/ is gone. The scene feature has scene-bar/, tools/ and annotation/. In shared/ the badge, the alert and the blank-title check sit directly next to ui/.
  • Directions linted. shared/, core/ and map/ may not import from features/. It was tried with a deliberate bad import and failed with a message. No new package.

How it was checked

CheckResult
BehaviourAll 264 client tests pass. Only their import paths changed.
Lazy boundaryThe production build shows map-viewer as a 7.85 kB lazy chunk, and the scene chunk 8 kB smaller.
BoundariesA deliberate import of the scene feature from shared/ failed lint with the new message.
BuildFormatting, lint with the class check and the production build are clean.

Not verified

The app was not opened after the move. If the dev server was running before, restart it, because it reads the path aliases only at start.
