UI polish and a guide

Task 021In progressfeat/ui-polish

The app has its own icon and name instead of the Angular starter's, the form tells you what to do next once you have placed something, and the README now says what the app is for, how to use it, and what is worth a reviewer's time.

How to see it

Reload the app's tab: the title reads "Twin Atlas" and the tab shows a white map pin on a dark square. Place a marker and watch the hint change from "Click the map to place the marker" to "Placed. Add a title and save, or click again to move it." Then open the README at the top of the repository. I have not looked at the icon in a real tab.

What was built

  • The app's own icon. A white map pin on a dark square, drawn by hand as an SVG, plus two PNG versions for browsers that ignore SVG icons and for the home screen. Angular's icon file is removed. No tool or package was added: the PNGs were drawn from the SVG by the Chromium that was already installed.
  • A real page title. It was "Client", the starter's default. It now reads "Twin Atlas", with a description and a theme colour.
  • A hint that moves on. After you place a marker, the form no longer asks you to click the map again. A note and an outline have their own wording.
  • A README for a newcomer. It says what problem the app solves and what it is not, walks through a first five-minute session in the order that makes sense (make a scene, add a marker, find it, edit it, watch a conflict being refused, share a link, load real map data), and ends with what a reviewer should look at, each point with its evidence.

How it was checked

CheckResult
IconsThe three icon files were rendered and then looked at as images. The build output contains them, the old Angular favicon.ico is not in it, and the page title in the build is "Twin Atlas".
Tests197 client tests pass (3 new, for the hint). Breaking the hint on purpose fails two of them. Two older tests were asserting the old wording while the fixture had the shape already placed, and now say what they mean.
READMEEvery step of the first session was checked against the code and the app's own texts. The import commands match what I ran against the live server earlier (35 of 35, and a repeat adds nothing). Its 24 links resolve.
BuildLint with the class check, formatting and the production build are clean.

Not verified

How the icon looks in a real browser tab, and the README's seventh step, where the address bar follows your selection. That one is covered by router tests only. Both need a look in a browser.

Left for later

  • Map labels overlap where markers are dense.
  • Imported titles such as "OSM node/1361887169" are noisy.
  • A separate user guide in docs/. The README carries the five-minute path for now, and a fuller guide would belong in the documentation site if the app grows.
