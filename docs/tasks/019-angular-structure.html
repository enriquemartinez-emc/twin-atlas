Angular structure and routes

Task 019In progresschore/angular-structure

The client now follows Angular's recommended structure, has real addresses for scenes and annotations, and no longer copies state between signals with effects. Nothing looks different on screen.

How to see it

Start the app with ./dev.sh, pick an annotation, and look at the address bar: it now reads like /scenes/<scene id>?annotation=<annotation id>. Paste that address into a new tab and the same scene and annotation open. I have not seen any of this in a browser yet, and I will not run the app without your approval.

What was built

  • Angular's layout. Each feature has its main component named after it (scene.ts), a components/ folder for its parts, its routes, and services named for the data they hold (scene-data.ts, annotation-data.ts). The old .page.ts, .service.ts and dotted names are gone, and so is the empty asset folder.
  • Real addresses. /scenes shows the scene you used last, /scenes/<id> shows that scene, and ?annotation=<id> selects an annotation. Anything else shows a not-found page with a way back. Every page has a title.
  • One route, on purpose. With two routes the router would rebuild the page, and the 3D map with it, the first time you pick a scene. One route with a custom matcher keeps both. A test guards it.
  • No copying between signals. The annotation data now receives the scene, the map view and the selection as signals, so nothing has to be pushed into it. Half-finished edits reset by themselves when you choose another annotation.
  • A narrower import rule. A component may import a file from its parent folder, which is how components/ reaches its feature. Climbing further, or into another feature's folder, is still refused.

Found on the way

  • My spec said the page would shrink. It grew from 440 to 531 lines, because the routing inputs and the self-resetting edit state live there now. It still does too much. Splitting it is the next step.
  • A test that proved nothing. The first edit-reset test passed even when I broke the code, because the editor was not on screen either way. It now waits for the second annotation to load.
  • Shadowed names. Turning the annotation data into a function made two local names hide the ones they came from. The compiler caught both.

Known limits

  • An address with a scene id that does not exist shows the generic "could not load" message, not a not-found page.
  • /scenes is not rewritten to /scenes/<id>, so the address bar stays short until you choose a scene.
  • The scene page is still large.
