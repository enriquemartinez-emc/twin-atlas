Project rules and repository setup

Task 001Donechore/agents-md-fixes

Before any code, the project got a git history and a written rulebook, so every later task is small, checked and easy to review.

Try it

Open AGENTS.md at the top of the repository: it is the rulebook. Open the specs/ folder: one file per task with its acceptance criteria and status. Run git log --oneline to see the small, labelled commits.

What was built

  • A git history. One bootstrap commit on main holds the rulebook and a .gitignore. It was a one-time exception: everything after that lives on feature branches.
  • A rulebook without contradictions. The original draft required tools it also called unapproved (formatters, the linter, Docker, the API client generator). Those are now approved and named. The folder layout, the Angular 22 constraints and a measurable scale target were written down.
  • A specs folder. Every task has a short file with a description, acceptance criteria and a status that moves from Proposed to Done only after you confirm.
  • Rules added as work went on: browser tests may be written but only run when you approve; small tasks can be batched; Angular components are single files; every task gets a page on this site.

Why it works this way

  • Criteria before code means you agree on what "done" is before anything is built, and the result can be checked against it.
  • Feature branches and Conventional Commits keep history readable: each commit says what kind of change it is and why.
  • Approval for new libraries keeps the dependency list short and deliberate.
