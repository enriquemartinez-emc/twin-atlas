OpenStreetMap import

Task 010In progressfeat/osm-import

A whole extract of real map data (shops, landmarks, building outlines) can be poured into a scene in one request. What cannot be used is skipped, and the answer lists every skipped element with the reason.

Try it

Create a scene that covers the fixture, then import it twice:

curl -X POST localhost:8080/api/scenes -H 'Content-Type: application/json' -d '{"name":"Sagrada Familia","extent":{"type":"Polygon","coordinates":[[[2.17,41.40],[2.18,41.40],[2.18,41.41],[2.17,41.41],[2.17,41.40]]]}}'

curl -X POST localhost:8080/api/scenes/SCENE_ID/imports/osm -H 'Content-Type: application/json' --data @server/src/test/resources/osm/overpass-sagrada-familia.json
# received 9, imported 4, and 5 rejected with their codes

# the same call again: imported 0, and every element says why it was skipped

The imported items are drafts. They appear in the list and on the map like anything you drew yourself. There is no import button in the app yet.

What was built

  • A new slice, importing. Its pure core turns an OpenStreetMap element into the same command a person would send to create one annotation. It does not decide whether that annotation is acceptable.
  • The same rules, not a copy. Each converted element goes through the rules of creating an annotation. "Valid shape", "inside the scene" and "title free" mean exactly what they mean there. The import only adds three rules about the source (table below).
  • Every problem at once. Everywhere else the first failed rule is reported. A bulk import is the one exception: a list of 3,000 shops must not stop at shop number 4. Each element gets its own answer.
  • One round trip. The server inserts all accepted annotations in a single batch. The database's unique title index decides conflicts, so two imports running at once cannot create the same annotation twice.
  • Titles carry the map reference, for example Bar Pep (node/123). Two places called "Bar" stay apart, and importing the same extract again is recognised as a repeat.
  • Three new error codes in the contract. The generated client was rebuilt, and the app's list of readable messages refused to compile until the three had sentences.

The scene does not exist404 SCENE_NOT_FOUND

Skipped elements are not errors of the request, so they are not HTTP errors. The request succeeded and the answer says what it did.

Why it works this way

The reasoning, the alternatives and the consequences are in ADR 0011. Terms such as node, way and Overpass are in the glossary.

Found on the way

  • One of my own tests was luck. It compared the skipped elements with a list built by Map.of, which has no fixed order. It passed at first, then failed when I broke the code on purpose for an unrelated check. It now uses an ordered map and passed three runs in a row.

Not verified

The two test files differ on purpose. One is a real extract, downloaded from the public Overpass service (20 amenities and 15 buildings in the Eixample; phone, e-mail and website tags removed). It imports completely, so it proves real data is understood but contains nothing the import has to turn away. The skipped-element cases come from the second file, which is written by hand in the same format with made-up ids. So no real data containing relations, open ways or broken shapes has been tried. There is no screen for importing. In the approved browser run of 2026-10-29 (headless Chromium with software rendering, against the real server and database), the live server imported the real extract (35 of 35), a repeat imported nothing, the hand-written file reported its five skipped elements with their codes, and the imported annotations were seen on the map. How long a full 5,000-element request takes was not measured.

Known limits

  • Relations (buildings with courtyards, for example) are skipped.
  • Renaming an imported annotation frees its old title, so importing the same extract again would create it a second time.
  • Updates in OpenStreetMap are not followed. Re-importing never changes what is already there.
  • The map must credit "© OpenStreetMap contributors" wherever imported data is shown. The endpoint's description says so, and the screen that offers imports will have to show it.
  • A request holds at most 5,000 elements. Larger extracts have to be sent in several requests.
