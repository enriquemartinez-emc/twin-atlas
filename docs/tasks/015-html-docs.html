Task 015In progressdocs/html-docs

This site: plain HTML pages that explain what was built, task by task, for someone who has not read the code.

Try it

Open docs/index.html in a browser (double-click it, or run xdg-open docs/index.html on Linux). It needs no server and no internet connection.

What was built

  • A front page with a status board of every task and a system map whose boxes link to the task that built them.
  • An architecture page and a glossary that explains the terms in plain words.
  • One page per finished task. Each has a plain-words summary, how to try it, what was built, a diagram, why, how it was checked and known limits, including what is not verified.
  • One stylesheet, no scripts and no libraries. The one font, Geist Mono, is stored in the repository, so nothing is fetched from the internet.
  • A workflow rule: from now on every task adds its own page before it is confirmed.

Layout

docs/ index.html status board and the clickable system map architecture.html how the pieces fit together glossary.html plain-language terms tasks/ NNN-name.html one page per task _template.html copy this to start the next one assets/docs.css the only stylesheet assets/fonts/ Geist Mono (SIL Open Font License) and its licence adr/ decision records (Markdown) openapi.json the API contract

The look

Light theme, Geist Mono for everything, solid soft fills with thin solid borders. No gradients, no shadows, no animation. Colour is used for meaning, and the same meaning on every page:

ColourMeansExample
BlueThe browserMap viewer, screens
GreenPure rulesThe decision functions
YellowServer codeEndpoints, platform
PurpleDataPostGIS tables
GreyTooling or generated codeAPI client, contract, your decisions in the workflow
RedErrors and things not verifiedRejections, "Not verified" notes

Adding a page for the next task

  1. Copy docs/tasks/_template.html to docs/tasks/NNN-name.html and fill it in. Keep to the same sections.
  2. Add the task to the sidebar of the other pages and to the status board on index.html.
  3. Explain any new term once in the glossary and link to it.
  4. Open the page in a browser, check it on a narrow window, and check every link.

How it was checked

CheckResult
LinksA script followed every internal link and anchor in every page. All resolve.
External resourcesNone are loaded. The font is a local file with its licence beside it. The only external addresses are plain links to ion.cesium.com.
Real browserPages were rendered in headless Chromium at desktop and phone width and inspected.
Page structureA parser confirmed every page has balanced tags, one main landmark and titled diagrams.

Known limits

  • The pages are written by hand, so the status board and sidebars must be updated when a task finishes. A generator would remove that chore but adds tooling the rulebook does not approve.
  • Decision records stay in Markdown and are linked, not converted.
