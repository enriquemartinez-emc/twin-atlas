Portfolio polish

Task 012In progressdocs/portfolio-polish

The repository now explains itself to a newcomer in five minutes: a README, a roadmap, and the two decision records that were missing.

How to see it

Nothing needs to run. Open README.md at the top of the repository, then follow its links. The README has a quick start for when you do want to run the app, and I have not run it.

What was built

FileWhat it is for
README.mdWhat Twin Atlas is, what works today, how to start it, how to test it, how it is built, with the benchmark numbers.
ROADMAP.mdWhat is done, what is next, what is paused, and what was left out on purpose.
docs/adr/0013Why the server is one deployable packaged by feature, with the boundaries enforced by tests.
docs/adr/0014Why the client uses Spartan components, and what that costs.

What was checked and fixed

  • The decision records are complete. The rules list the decisions that must be written down. Two were missing: the modular monolith and the choice of Spartan. Both now exist, and the index lists all 14.
  • The architecture notes were stale. They still described the OpenStreetMap import as planned. Fixed, and they now name the shared kernel and the UI rules.
  • The client's command table now shows the lint command that includes the class-bloat check.

How it was checked

CheckResult
Links72 links in the README, roadmap, architecture notes, decision-record index and specs index all resolve. No placeholder text remains.
SpecsEvery spec file shows the same status as the specs index.
A clean cloneA fresh clone of the branch: the server build with formatting check and all tests gives 192 passing tests. The client installs from its lock file, and lint, formatting, 182 passing tests and the production build pass. Regenerating the SDK from the committed contract leaves no difference.
The benchmark claimThe numbers in the README are copied from the benchmark results, not recalled.

Not verified

The README has three screenshots, taken in the approved browser run of 2026-10-29 (headless Chromium with software rendering, against the real server and database). It has no recording. The quick-start commands were run from the working checkout (database, server, client), not from the clean clone: the clean-clone check ran tests and builds only. The Swagger UI address in the README is springdoc's default and I have not opened it.

Known limits

  • The screenshots show the OpenStreetMap globe. The photorealistic 3D tiles need a Cesium ion token that only you can create.
  • npm 12 warns during installation that some packages' install scripts were not approved. The build and every test still pass.
  • The README's benchmark paragraph is a summary. The method, hardware and plans are in the decision record.
