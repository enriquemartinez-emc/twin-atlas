Spring Boot structure

Task 020In progresschore/spring-structure

The server's biggest feature folder had 21 files of mixed roles. It is now split into web, persistence and core, with the dependencies between them one-way and enforced by the build. Nothing changes for the API or the screen.

How to see it

Open server/src/main/java/com/twinatlas/annotation in your editor: six files at the top, and three folders. Nothing needs to run. I have not started the app for this task.

What was built

  • Role folders inside the big feature. web/ has the endpoints and the request shapes. persistence/ has the database side: entity, repository, mapper, the facts the rules need, the SQL reads and their inputs. The base folder keeps only what the feature returns. core/ is unchanged.
  • Configuration in its own place. The two configuration classes moved to platform/config/, the conventional name.
  • One-way dependencies, checked. Web calls persistence, persistence returns the shapes in the base folder, and both use the core. Three rules fail the build if anything points the other way.
  • Small features stay flat. scene has 6 files and importing has 4, so folders would be noise. The rule of thumb is to split once a package passes about 8 files, and it is written in the rulebook.

What I did not do, and why

I did not switch to top-level controller/, service/ and repository/ packages. That is packaging by layer across the whole app, which your rulebook and ADR 0013 forbid, and Spring Boot's own guide shows feature packages. If you want the layered style anyway, it is a rule change first and a big move after. Spring Modulith would make these module boundaries a Spring feature, with its own verification test. It is a new dependency, so it is a proposal and needs your approval.

How it was checked

CheckResult
The whole backend buildFormatting check and 193 tests pass against a real PostGIS database, on the final tree.
The API did not changeThe committed contract is identical and its drift test passes without regenerating. The client was not touched.
The new rules can failA persistence class using a web class, a returned shape using persistence, and a core using persistence each failed their rule. All three were undone.
A mistake, found and fixedA malformed test command of mine left a stray line in AnnotationPage.java. The build still passed with it. I found it by reading the diff, removed it and ran everything again.
Docker went awayDocker vanished from this machine's Linux side mid-task and killed one build. The tests that need no Docker ran meanwhile, and the full build ran again once Docker was back.

Not verified

The running app. The tests exercise every endpoint against a real database, but I did not start the server and client after the move.

Known limits

  • Classes the endpoints use from persistence/ are now public instead of package-private. Other features still cannot reach them, and the build checks it.
  • The folders inside annotation are a judgement about readability. They do not change behaviour, so another split would be just as valid.
  • Splitting scene and importing is left for when they grow.
