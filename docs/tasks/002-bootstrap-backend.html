Backend housekeeping

Task 002Donechore/bootstrap-backend

The server skeleton that Spring Initializr generated was moved into place and cleaned up to match the rulebook.

Try it

From the repository root: cd server && ./mvnw verify. It compiles, runs the context-load test and builds twin-atlas-server-0.0.1-SNAPSHOT.jar.

What was built

  • Moved the project from twinatlas/ to server/, next to client/.
  • Renamed the Java package from com.example.twinatlas to com.twinatlas, the application class to TwinAtlasApplication and the artifact to twin-atlas-server.
  • Removed Lombok and the Spring dev tools. Neither was in the approved stack, and Lombok works against the plain-records style the project uses.
  • Used the Java 25 that was already installed. No new tools were added.

Before and after

Before

twinatlas/ pom.xml com.example, Lombok, devtools src/main/java/ com/example/twinatlas/ TwinatlasApplication.java

After

server/ mvnw, pom.xml com.twinatlas, no Lombok src/main/java/ com/twinatlas/ TwinAtlasApplication.java

How it was checked

CheckResult
./mvnw verify with Java 25Passes. The context-load test is green and the jar builds.
Leftover com.example referencesNone (searched the sources and the pom).

Known limits

  • Java was on the path only in a login shell, so commands set JAVA_HOME explicitly. Export it in your shell profile if ./mvnw cannot find Java.
