Backend foundation

Task 004Donechore/backend-foundation

The database, the error format, GeoJSON support and the rules that keep the server tidy: everything the feature work stands on.

Try it

docker compose up -d
cd server && ./mvnw spring-boot:run
curl localhost:8080/actuator/health

The answer is {"groups":["liveness","readiness"],"status":"UP"}. The API documentation is at http://localhost:8080/swagger-ui/index.html.

What was built

  • A database for development. docker-compose.yml starts PostgreSQL with PostGIS (postgis/postgis:17-3.6) with a health check and memory settings that keep it small. Tests use the very same image, and a test fails if the two ever differ.
  • Schema by numbered files. Flyway owns the database structure. Hibernate only checks that it matches.
  • Errors in one format. Every error is an RFC 7807 problem with a stable code.
  • GeoJSON in and out through jackson-datatype-jts, an existing library built for the current Jackson. A custom serializer was planned and dropped once the library turned up.
  • Clock, ids and the geometry factory as beans, so the pure rules receive time and ids as parameters.
  • Architecture tests that fail the build when the structure is broken (diagram below).
  • Automatic formatting check with Spotless, bound to verify.

Why it works this way

Coordinates are stored as plain longitude and latitude with an index, so the same data works for maps and for the API (ADR 0001). Maven is the build tool because the project is a single module and its fixed lifecycle is easy to read (ADR 0002).

Known limits

  • The Compose stack runs only the database. There is no server container yet.
  • google-java-format is pinned to 1.36.0 because 1.37.0 fails inside the Spotless plugin.
  • One test logs the same error twice. It looks like a test-tool quirk and was not investigated further.
