Figtree font and a Spartan-built UI

Task 017In progressfeat/ui-figtree-spartan

The app now uses the Figtree font, and its panel, alerts, tool buttons, list rows and form fields come from Spartan components instead of long strings of style classes.

How to see it

I have not run the app for this task, and I will not without your approval. When you want to look, the three commands are the same as before: docker compose up -d, then ./mvnw spring-boot:run in server/, then npm start in client/. You can check the class rule without running anything: npm run lint:classes in client/.

What was built

  • The Figtree font. It is a variable font: two small files (30 KB together) cover every weight. They are stored in the project with their licence, declared once, and used by the whole UI. Nothing is fetched from the internet and no package was added. This documentation keeps its own font, Geist Mono.
  • Eight more Spartan components, added with Spartan's own tool and no new package: card, alert, badge, separator, toggle group, item, field and typography.
  • The panel is a card, errors and warnings are alerts, the tool choice is a toggle group, each annotation is an item with a badge for its kind, and every label, input and message sits in a field.
  • One small alert component for messages the user must see, so the markup is written once instead of ten times.
  • A rule that holds. A short script fails the lint step when an element has more than four utility classes. It is recorded in AGENTS.md next to the font choice.

Found on the way

  • My first test proved nothing. I checked the pressed state of the tool buttons, then broke the code on purpose by freezing the group's value, and every test still passed. The group tracks clicks by itself. A second test, for the case where the app changes the tool (Cancel returns to Select), does fail on that break.
  • The new check found two more offenders in the app shell, which I had not touched. Fixed.
  • A stale test. One setup test asserted that a Tailwind class existed on the shell. It now asserts that Spartan's typography delivers its classes.
  • Nine style errors in the generated files (imports used only as types). The linter fixed them in place, as the rules allow.

Not verified

I have not seen any of it in a browser: the spacing, the look of the panel and how the font renders are unchecked. A look needs your approval to run the app.

Known limits

  • Spartan's field error shows itself from the state of its own form helpers, which do not know about Signal Forms. It is used here as a styled message inside our own checks.
  • The scene chooser is a plain select. Spartan's version needs an icon library, which is a new package and needs your approval.
  • The Spartan components themselves carry long class strings. That is by design: it is where those classes belong.
  • The map controls and dark mode were not redesigned.
