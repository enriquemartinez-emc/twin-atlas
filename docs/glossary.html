Glossary

Plain-language explanations of the terms that come up in these pages.

Cesium ion token

Cesium ion is a hosted service from the makers of CesiumJS that streams 3D map data to browsers. Twin Atlas uses it to load Google's photorealistic 3D buildings.

A token is a long secret-looking string, like a key, that tells ion which account is asking. You get one for free: create an account at ion.cesium.com, open its access tokens page and copy the default token. Paste it into the Map panel in the app. It is kept in your browser only, never in the code or sent to our server.

Without a token the app still works: it shows an OpenStreetMap globe instead of the 3D buildings. Account plans and limits are set by Cesium and can change, so check their site.

ETag and If-Match

An ETag is a label the server attaches to a response that says which version of a thing you are looking at. Here it is a small counter that goes up every time an annotation changes. A newly created annotation arrives with ETag: "0".

When you later edit it, the app will send that label back in an If-Match header. If someone else changed the annotation in the meantime, the labels no longer match and the server refuses the edit instead of silently overwriting their work. This is called optimistic locking.

Editing uses it (task 014): the screen sends the version it read, and if that version is no longer the current one the server answers 412 and the screen offers to load the latest version.

Functional core, imperative shell

A way to split code. The core is pure functions that make decisions. The shell does the input and output around it: it loads facts, calls the core, and saves the result. See how it fits together.

Rejection and problem code

When a rule says no, the core returns a short stable name such as TITLE_ALREADY_USED. The server turns it into an HTTP error with that name as its code, and the app turns the code into a readable sentence. The names never change, so other systems can rely on them.

PostGIS and GiST index

PostGIS adds maps to the PostgreSQL database: points, polygons and questions like "what is inside this area". A GiST index is the structure that lets it answer those questions without reading every row.

Bounding box (bbox)

The rectangle of the map you can currently see: west, south, east, north in degrees. The app asks the server only for what is inside it.

Keyset pagination and cursor

Showing a long list a page at a time. Instead of "skip the first 400" (slow and unreliable when data changes), each page ends with a cursor, a note of where it stopped, and the next request continues from there.

SRID 4326 and GeoJSON

SRID 4326 is the ordinary longitude and latitude used by GPS. GeoJSON is the standard way to write points and polygons as JSON, for example {"type":"Point","coordinates":[2.17,41.40]}. The order is longitude first.

OpenAPI and SDK

OpenAPI is a machine-readable description of every endpoint. An SDK is code written for you from that description so the app can call the server without hand-writing types. In this project both are generated and checked, never edited by hand.

Flyway migration

The database structure is changed only through numbered files that run in order. Anyone can rebuild the exact same database from them.

Testcontainers, ArchUnit, jqwik

Testcontainers starts a real PostGIS database for tests. ArchUnit tests the structure of the code (who may depend on whom). jqwik runs a rule against thousands of random inputs instead of a few hand-picked ones.

Signals, Signal Forms, zoneless

Modern Angular ideas used in the app. Signals are values that tell the screen exactly what to update. Signal Forms build forms on them. Zoneless means Angular does not use the older zone.js machinery to guess when to refresh.

3D Tiles and the digital twin

A digital twin is a detailed 3D copy of a real place. 3D Tiles is the format that streams such a copy to a browser in pieces, only the parts you are looking at.

Latency, p50 and p95

Latency is how long a request takes. Averages hide slow outliers, so results are given as percentiles: p50 is the median (half of requests were faster), p95 means 95 out of 100 requests were at least that fast, and p99 is the same for 99 out of 100. If p95 is close to p50 the system is consistent.

OpenStreetMap, Overpass, nodes and ways

OpenStreetMap (OSM) is a free map of the world that volunteers edit, a bit like Wikipedia for places. Its data is available under the Open Database License (ODbL): you may use it, but you must credit "© OpenStreetMap contributors".

The map is built from three kinds of element. A node is a single point, such as a shop. A way is a line made of points: when it closes on itself it is an area, such as a building, otherwise it is a street or a path. A relation groups other elements, for example a building with a courtyard. Each element can carry tags, which are labels such as name=Bar Pep or building=yes.

Overpass is a public service that answers questions such as "every shop inside this rectangle" and returns them as JSON. Task 010 imports such an answer into a scene.

Shared kernel

A shared kernel is a very small set of types that several parts of a program agree on, so that they can talk to each other without depending on one another. Here it is the answer type Decision and the list of error codes Rejection: every feature's rules return them, and one place turns them into web errors.

It is kept tiny on purpose, because everything in it couples every feature. See ADR 0012.

Variable font

A normal font ships one file per weight: regular, medium, bold and so on. A variable font is a single file that holds every weight in between, so the page asks for one small file and can use any weight from thin to black. Figtree, the font of the app, is one.

Utility class and class bloat

A utility class is a tiny style name such as px-4 (horizontal padding) or font-medium. Tailwind, the styling tool of the client, is made of thousands of them, and a template that spells out ten of them on one element is hard to read. That pile is called class bloat.

The project keeps classes inside Spartan's ready-made components, or in the component's own style block, and a check fails the build when an element has more than four. See the UI task.

Query plan, sequential scan and index scan

Before running a query, the database picks a plan. EXPLAIN ANALYZE shows the plan it chose and how long each step really took. A sequential scan reads every row. An index scan jumps straight to the matching rows, which is what makes a query on a million rows as fast as one on a thousand.

ADR

Architecture decision record: a one-page note saying what was decided, what else was considered, and the consequences.
